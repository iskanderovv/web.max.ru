# Web Chat на GREEN-API

Тестовое задание «Фронтенд разработчик React»: веб-интерфейс чата для отправки и получения текстовых сообщений через [GREEN-API](https://green-api.com/telegram).

> **Мессенджер и внешний вид.** Задание просит взять за прототип внешний вид чата [web.max.ru](https://web.max.ru/) и разрешает использовать WhatsApp или Telegram, если MAX недоступен. В консоли GREEN-API для моего аккаунта доступны только тарифы WhatsApp и Telegram, поэтому в качестве бэкенда используется **Telegram**, а интерфейс повторяет web.max.ru: цвета тёмной темы, градиенты пузырей, радиусы и размеры взяты из дизайн-токенов и вёрстки самого MAX, иконка вкладки — оригинальная иконка web.max.ru. Код, зависящий от мессенджера, сосредоточен в `src/api/`, остальной интерфейс от него не зависит.

## Возможности

Сценарий из задания:

1. Вход по данным инстанса GREEN-API (`idInstance`, `apiTokenInstance`).
2. Создание чата по номеру телефона получателя (форма «New Contact»: имя, фамилия, номер).
3. Отправка текстового сообщения (`SendMessage`).
4. Получение ответа (`ReceiveNotification` + `DeleteNotification`) и отображение в чате.

Дополнительно:

- Поиск по чатам, контактам, группам, каналам и ботам. Пользователя или бота можно найти по точному `@username` (`checkAccount`).
- Список контактов с фотографиями и статусом **online / last seen** (`getContactInfo`).
- Статусы доставки: ✓ отправлено, ✓✓ прочитано (уведомления `outgoingMessageStatus` и `getChatHistory`).
- Редактирование и удаление своих сообщений (`editMessage`, `deleteMessage`), удаление чата и очистка истории.
- Отправка индикатора «печатает» собеседнику (`sendTyping`), подгрузка последних сообщений при открытии чата.
- Адаптивная вёрстка в стиле MAX: боковая панель разделов (Chats, Unread, Channels, Contacts, Settings), на телефоне она превращается в нижнюю панель.
- SEO-разметка (meta, Open Graph, JSON-LD, `robots.txt`) и число непрочитанных сообщений в заголовке вкладки.

## Подготовка инстанса GREEN-API

> Для проверки нужен инстанс **Telegram**. MAX в этой работе реализован только как внешний вид.

1. Зарегистрируйтесь на [green-api.com](https://green-api.com) и создайте инстанс **Telegram** (тариф Developer, бесплатный).
2. Авторизуйте инстанс: в консоли откройте QR-код, в Telegram на телефоне выберите _Настройки → Устройства → Подключить устройство_ и отсканируйте его. Статус должен стать `Authorized`.
3. Включите уведомления: в консоли инстанса _Изменить_ → «Получать уведомления о входящих сообщениях» и «о статусах отправленных сообщений», либо вызовите `SetSettings` с `{"incomingWebhook": "yes", "outgoingWebhook": "yes"}`. Поле `webhookUrl` должно быть пустым. Если уведомления выключены, приложение покажет предупреждение с кнопкой «Turn on», которая включает их за вас.
4. Скопируйте `apiUrl`, `idInstance` и `apiTokenInstance` из консоли.

## Как пользоваться

1. Откройте приложение и введите `idInstance` и `apiTokenInstance`. Поле `apiUrl` подставляется автоматически из `idInstance`, при необходимости его можно изменить.
2. Нажмите синюю кнопку «+» в списке чатов (или «Add contact» в разделе Contacts), введите имя и номер получателя в международном формате.
3. Напишите сообщение: Enter отправляет, Shift+Enter переносит строку.
4. Попросите получателя ответить из Telegram. Ответ появится в чате через несколько секунд.

## Архитектура

```
src/
  app/            корень приложения (App, завершение сессии)
  api/            fetch-клиент GREEN-API, очередь запросов, квоты, Zod-схемы
  features/
    auth/         вход, хранилище учётных данных
    chats/        список чатов, окно чата, сообщения, получение уведомлений
    contacts/     контакты, добавление контакта, фотографии
    search/       поиск по чатам, контактам и @username
    settings/     профиль, настройки уведомлений инстанса
    shell/        раскладка, боковая панель разделов
  shared/         общие компоненты, хуки и утилиты
  styles/         дизайн-токены и глобальные стили
tests/
  unit/           модульные тесты (api, хранилища, утилиты, хуки)
  integration/    сценарии на уровне интерфейса, по одному файлу на функцию
  helpers/        fetch-заглушка, рендер приложения, примеры уведомлений
```

Зависимости направлены в одну сторону: `app → shell → features → shared → api`.

Ключевые решения:

- **Получение сообщений.** Цикл `receiveNotification` (long-poll 20 с) → обработка → `deleteNotification`. Уведомление удаляется даже при ошибке обработки, иначе очередь FIFO остановится. При сетевых ошибках пауза растёт экспоненциально (1 → 30 с). Дубликаты отсекаются по `idMessage`.
- **Только открытые чаты.** Инстанс привязан к реальному аккаунту, поэтому в интерфейс попадают сообщения только из чатов, которые пользователь открыл сам. Остальные уведомления удаляются из очереди и не отображаются.
- **Оптимистичная отправка.** Сообщение сразу появляется со статусом «отправляется», затем получает ✓ или ❗ с повторной отправкой по клику.
- **Единая очередь запросов.** Все вызовы API идут через планировщик с интервалами по методам (у части методов лимит 1 запрос/с), пользовательские действия обгоняют фоновые, при HTTP 429 выполняется автоматический повтор.
- **Квоты тарифа.** При HTTP 466 исчерпанный метод запоминается до конца месяца и больше не вызывается. Необязательные запросы (фотографии контактов) ограничены собственным месячным бюджетом.
- **Валидация ответов API.** Все ответы проходят через Zod, неожиданная форма даёт понятную ошибку.
- **CORS.** GREEN-API отвечает `access-control-allow-origin: *`, поэтому запросы идут напрямую из браузера, бэкенд не нужен.

## Тестирование

Тесты разделены на модульные (`tests/unit`) и интеграционные (`tests/integration`). Интеграционные рендерят приложение целиком и подменяют `fetch`, то есть проверяют реальные сценарии пользователя: вход, создание контакта, отправку, получение, статусы, поиск, редактирование и удаление, квоты.

```bash
npm test
npm run coverage
```

## Ограничения

- **Квоты тарифа Developer.** Каждый «сервисный» метод GREEN-API (`getContactInfo`, `checkAccount` и другие) ограничен примерно 100 вызовами в месяц, затем API отвечает HTTP 466 (`QUOTE_EXCEEDED`). Поэтому статус online / last seen запрашивается один раз при открытии чата, а в списке контактов показывается только из кэша. Кроме того, тариф ограничивает число чатов в месяц.
- **Статус online приблизителен.** API не присылает события присутствия, только `lastSeen` (`0`, если скрыто настройками приватности).
- **Нет индикатора «собеседник печатает».** GREEN-API такие события не отправляет.
- **Поиск ограничен аккаунтом.** `getChats` возвращает только диалоги самого аккаунта, поэтому произвольный публичный канал по названию не найти. Пользователя или бота можно найти по точному `@username`.
- **Только текстовые сообщения** (по условию задания).

## Безопасность

`apiTokenInstance` хранится только в `localStorage` браузера пользователя и отправляется только на хост GREEN-API. В репозиторий токены не попадают. В промышленной версии токен следует хранить и использовать на сервере: здесь это сознательно упрощено условиями задания (чисто клиентское приложение).

## Что можно улучшить

- Тонкий бэкенд-прокси, чтобы токен инстанса не хранился в браузере.
- Уведомления через webhook вместо long-polling.
- E2E-тесты (Playwright) поверх существующих интеграционных.
- Локализация интерфейса и поддержка MAX-инстансов (отличаются метод поиска контакта и формат `chatId`).
